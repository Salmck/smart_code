# 手机号验证码登录系统（FastAPI）

一套「填手机号 → 人机验证 → 收验证码 → 登录」的完整实现。当前为**测试模式**，
不依赖任何外部短信 / 验证码服务，克隆下来即可跑通全流程。

## 快速开始

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

uvicorn app.main:app --reload
```

打开 http://127.0.0.1:8000

- 输入任意合法手机号（如 `13800138000`）
- 完成人机验证（一道算术题）
- 点「获取验证码」——验证码会打印在**服务端控制台**；DEBUG 模式下也会自动填入输入框
- 点登录

## 登录流程

```
浏览器                          后端
  │  GET /api/captcha            │  下发一道人机验证挑战
  │ ───────────────────────────>│
  │  POST /api/send-code         │  ① 手机号格式校验
  │   {phone, captcha_id, ans}   │  ② 后端校验人机验证（前端结果不可信）
  │ ───────────────────────────>│  ③ 频率限制（防刷/防轰炸）
  │                              │  ④ 生成验证码 → 存储 → 发短信
  │  POST /api/login             │  校验验证码 → 一次性作废
  │   {phone, code}              │  → 签发 JWT 登录凭证
  │ ───────────────────────────>│
  │  GET /api/me (Bearer token)  │  受保护接口，演示登录态
  │ ───────────────────────────>│
```

## 目录结构

| 文件 | 职责 |
|------|------|
| `app/main.py` | FastAPI 应用与所有接口 |
| `app/config.py` | 全部可调参数（有效期、频率限制、密钥等） |
| `app/captcha.py` | 人机验证（测试模式为算术题） |
| `app/sms.py` | 短信发送（测试模式打印到控制台） |
| `app/store.py` | 验证码 / 频率限制的内存存储 |
| `app/security.py` | JWT 签发与校验 |
| `static/index.html` | 前端登录页 |

## 已内置的安全措施

- **人机验证在后端二次校验**，且题目一次性使用
- **频率限制**：单手机号 60s 冷却 + 每日上限；单 IP 每小时上限（防短信轰炸刷钱）
- **验证码**：`secrets` 生成、5 分钟过期、登录成功即作废、限制猜测次数
- **JWT** 登录凭证，带过期时间

## 从测试模式切到生产

改配置（推荐用环境变量），并实现对应服务分支：

| 要做的事 | 在哪里改 |
|----------|----------|
| 关闭验证码回显 | `DEBUG=false` |
| 换真实短信 | `SMS_PROVIDER=aliyun`（或 tencent/twilio），在 `app/sms.py` 实现对应分支 |
| 换真实人机验证 | `CAPTCHA_PROVIDER=...`，在 `app/captcha.py` 实现，前端换成对应厂商 SDK |
| 换 Redis 存储 | 把 `app/store.py` 的读写换成 Redis（多实例部署必须） |
| 设置 JWT 密钥 | `JWT_SECRET=<强随机值>` |

> 提醒：国内真实短信需要企业实名 + 短信签名/模板审核（通常 1~3 天），
> 这是上线前最耗时的一步，代码本身反而最快。
